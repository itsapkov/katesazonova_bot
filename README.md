# katesazonova_bot — бот курса «КАПСУЛА FW 26/27»

Telegram-бот для Кати Сазоновой: рассказывает о ней и о курсе, отвечает на частые
вопросы и принимает оплату через **lava.top** — рублями (СБП / карта), евро и
долларами (Apple Pay / PayPal / карта). На каждый выбранный способ бот создаёт
**отдельную одноразовую ссылку** на оплату, а после оплаты сам присылает доступ
в тот же чат.

---

## 0. Сначала — безопасность

Токен бота был отправлен в переписке, то есть считается скомпрометированным.
Прежде чем запускать: @BotFather → `/mybots` → `katesazonova_bot` → *API Token* →
**Revoke current token**. Новый токен вписывается только в файл `.env`, который
никогда не попадает в git (он уже в `.gitignore`).

## 2. Настройка lava.top (это делает Катя, 15 минут)

lava.top — платформа для продажи цифровых продуктов. Она сама принимает деньги,
выдаёт чеки покупателям и выводит выручку. Комиссия — 8% с приходящих платежей.

1. Регистрация на <https://lava.top> и вход в личный кабинет автора.
2. Заполнить профиль автора и **добавить способ вывода средств**
   (без этого продукт нельзя опубликовать).
3. Создать продукт: тип «Цифровой товар / курс», название `КАПСУЛА FW 26/27`,
   описание, обложка.
4. В продукте задать **цены сразу в трёх валютах**: RUB, EUR, USD. Это
   принципиально: бот показывает три кнопки и просит у API счёт в выбранной
   валюте — если цены в EUR нет, кнопка «в евро» вернёт ошибку.
5. Опубликовать продукт.
6. Создать **API-ключ**: настройки кабинета → раздел API → создать ключ.
   Это значение пойдёт в `LAVA_API_KEY`.
7. Указать **вебхук** (адрес появится после деплоя, шаг 4):
   `https://<адрес-сервиса><LAVA_WEBHOOK_PATH>`, события `payment.success`
   и `payment.failed`. Если в интерфейсе вебхуки не нашлись — напишите в
   поддержку lava.top (@lava_sup_bot), они включают их по запросу.
   Без вебхука бот тоже работает: он сам опрашивает статус счёта раз в 30 секунд.

Про способы оплаты в API lava.top:

| Валюта | `paymentMethod` | Что видит покупатель на странице оплаты |
|---|---|---|
| RUB | `BANK131` | СБП и карты российских банков (МИР/Visa/MC) |
| EUR, USD | `UNLIMINT` | международные карты, Apple Pay / Google Pay |
| EUR, USD | `PAYPAL` | PayPal |

Кнопки «СБП» и «Картой» ведут в одну и ту же кассу (`BANK131`) — там покупатель
выбирает конкретный способ. Кнопка «Apple Pay» ведёт в `UNLIMINT`: Apple Pay
показывается на iPhone/Mac в Safari. Если у Кати в кассе Apple Pay появляется
через Stripe, а не Unlimint — поменяйте `UNLIMINT` на `STRIPE`
в `config.py` → `PAYMENT_METHODS`, строки `EUR_APPLE` / `USD_APPLE`.

## 3. Запуск локально (проверить, что всё работает)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# заполнить BOT_TOKEN, LAVA_API_KEY, ACCESS_URL, ADMIN_CHAT_ID

python tools/list_offers.py      # покажет offerId -> вписать в .env как LAVA_OFFER_ID
python bot.py
```

Бот подтягивает актуальные цены из lava.top при старте, поэтому кнопки не
разъезжаются с кассой. Значения `PRICE_*` из `.env` используются только как
подстраховка, если API недоступен.

Проверка боем: пройти путь до кнопки «Открыть оплату», заплатить рублём
(минимальную цену можно временно поставить в lava.top), убедиться, что доступ
пришёл в чат и что Кате упало уведомление.

## 4. Деплой (бот должен работать 24/7)

Бот использует long polling для Telegram и поднимает маленький веб-сервер для
вебхука lava.top — поэтому хостинг должен давать публичный адрес и порт.

### Railway / Render (проще всего, ~5–7 $ в месяц)

1. Залить папку в приватный репозиторий на GitHub.
2. Создать новый проект из этого репозитория. Dockerfile определится сам.
3. В разделе Variables прописать всё из `.env` (кроме `PUBLIC_URL`).
4. Получить публичный домен сервиса → вписать его в `PUBLIC_URL`, а
   `https://<домен><LAVA_WEBHOOK_PATH>` — в настройки вебхука lava.top.
5. Включить постоянный диск (volume) и указать `DB_PATH=/data/bot.sqlite3`,
   иначе база с покупателями будет теряться при каждом деплое.

### VPS (Hetzner / Timeweb, ~4 € в месяц)

```bash
git clone <репозиторий> /opt/katesazonova_bot && cd /opt/katesazonova_bot
cp .env.example .env && nano .env
docker build -t katebot . && docker run -d --restart=always \
  --env-file .env -p 8080:8080 -v /opt/katebot-data:/data katebot
```

Публичный HTTPS для вебхука проще всего сделать через Caddy или Nginx
с сертификатом Let's Encrypt.

## 5. Что править под себя в первую очередь

Всё в `texts.py`:

* `WELCOME` — приветствие Кати (лучше её собственными словами)
* `ABOUT_PAGES` — три экрана «о курсе»
* `PROGRAM` — реальные модули курса, помечено `>>> ПРАВКА <<<`
* `FAQ` — сроки доступа, формат, возвраты
* `COURSE_NAME` — если название курса другое

В `.env`: `ACCESS_URL` — ссылка, которая уходит после оплаты (инвайт в закрытый
Telegram-канал, Notion или папка на Google Drive). Для канала лучше сделать
инвайт-ссылку с заявками на вступление, чтобы её нельзя было бесконечно
пересылать.

Картинки-заголовки, как в референсном боте, добавляются легко: положить файлы
в папку `media/` и заменить `message.answer(...)` на `answer_photo(...)`
в нужных экранах — скажите, и я это допишу.

## 6. Юридический минимум

lava.top выступает платёжным посредником и выдаёт покупателю чек, но продавец
контента — Катя. Для приёма платежей понадобится статус самозанятой или ИП
(или другой статус, если она налоговый резидент Испании/Франции — это стоит
уточнить у бухгалтера, я не даю налоговых консультаций). Также нужны публичная
оферта и политика конфиденциальности — их можно разместить на странице продукта
в lava.top и сослаться из FAQ бота.
